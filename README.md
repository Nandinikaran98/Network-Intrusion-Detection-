# Network Intrusion Detection System (UNSW-NB15)

MCA Final-Year PBL Project - machine-learning system that classifies network traffic as
**Normal** or **Malicious**.  Three classifiers (Logistic Regression, Decision Tree, Random Forest)
are trained, evaluated, cross-validated, tuned with GridSearchCV; the best one is saved as a
complete pipeline and used by a command-line tool and a web form.

> **Quick start:** `pip install -r requirements.txt`, then `python app.py` (web form) or `python predict.py` (command line). Results are in `outputs/`.

## 1. Project structure

```
nids_project/

├── train.py              steps 1-9 + 11: EDA -> split -> 3 models -> CV -> GridSearchCV -> best model -> save

├── requirements.txt

    ├── tables/           every table as CSV (CV scores, best hyper-parameters, comparison ...)

```

## 3. Dataset

**UNSW-NB15** (UNSW Canberra Cyber): <https://research.unsw.edu.au/projects/unsw-nb15-dataset>

This repository uses the official partition file `UNSW_NB15_testing-set.csv`
(**82,332 records**, 45 columns: 37,000 normal + 45,332 attack records in 9 attack families).
It is already in `data/`, so nothing has to be downloaded.

* The project re-splits the data itself (80 % train / 20 % test, stratified) as required by the brief.
* 26,387 records (32 %) are exact duplicates once the `id` column is ignored; they are removed in
  step 3 so that identical rows cannot sit in both the training and the test set. **55,945 unique records** remain.
* Other UNSW-NB15 CSV files (e.g. the official training partition or the 4 raw files) can simply be added to
  `data/`; all CSVs there are merged automatically. Re-run `python train.py --data-dir data` afterwards.

## 4. Run

The trained model and all results are **already included** in `outputs/`, so the interfaces work immediately:

```bash
python predict.py                       # type the values, ENTER = default
python predict.py --example attack      # a real attack record from the test set
python predict.py --example normal
python predict.py --csv new_records.csv # many records -> new_records_predictions.csv
python app.py                           # web form at http://127.0.0.1:5000
```

To reproduce the whole training (about 3 minutes, results are identical because all seeds are fixed):

```bash
python train.py --data-dir data
```

Options of `train.py`: `--tune-sample 30000` (rows used for CV + GridSearchCV), `--max-rows N`,
`--fast` (smaller grids), `--test-size 0.2`, `--seed 42`.

## 5. How the project steps are implemented

| Step (project brief) | Where | What happens |
|---|---|---|
| 1 Load & understand | `train.py: step1_load`, `common.load_dataset` | reads CSVs with pandas; prints shape, column types, class counts, attack categories |
| 2 EDA | `step2_eda` | duplicates, missing values, imbalance, numeric/categorical summaries, 5 figures |
| 3 Prepare data | `step3_prepare`, `common.build_preprocessor` | X / y; duplicates removed; leakage columns dropped; one-hot encoding + log/standard scaling inside the pipeline |
| 4 Split | `step4_split` | 80 % train / 20 % test, stratified; train is split again into fit / validation so the **test set stays untouched** |
| 5 Three models | `step5_6_baseline`, `common.make_models` | Logistic Regression, Decision Tree, Random Forest |
| 6 Evaluate & compare | `step5_6_baseline` | accuracy, precision, recall, F1, ROC-AUC, confusion matrix, false negatives (validation set) |
| 7 Cross-validation | `step7_cv` | 5-fold stratified CV, five scores + mean per model |
| 8 Hyper-parameter tuning | `step8_tune`, `common.param_grids` | GridSearchCV (tree depth, number of trees, regularisation `C`, ...), best parameters + CV scores |
| 9 Best model | `step9_select_and_test`, `final_test` | tuned models compared on validation data; the best (highest attack F1) is re-trained on all training data and evaluated **once** on the test set |
| 10 New data | `predict.py`, `common.predict_records` | user input -> same preprocessing -> model -> "Normal Traffic" / "Malicious Traffic" |
| 11 Save & demo | `save_final`, `predict.py`, `app.py` | one `joblib` file with preprocessing + model; CLI and web form |

### Design decisions you should be able to explain

* **Attack = positive class.** The most important metric is **recall** (a missed attack = false negative is
  worse than a false alarm), together with precision / F1.
* **No data leakage:** `id`, `attack_cat` (derived from the label), IP addresses, ports, timestamps and TCP
  sequence numbers are not used as inputs. Scaling / encoding / imputing are part of the pipeline, so inside
  cross-validation they are learned from the training folds only.
* **Duplicates are removed** (32 % of the file) so identical rows cannot appear in both train and test.
* **Validation set:** the brief says the test set must stay untouched during model selection. Therefore models
  are compared on a validation split that is carved out of the training data; the test set is used only once.
* **Skewed numeric features** (bytes, packets, load) are log-transformed before scaling.
* **Cross-validation and GridSearchCV use a stratified training subset** (`--tune-sample`, default 30 000 rows)
  to stay fast, as allowed by the brief for large datasets. The final model is trained on all training rows.
* Detection rate for every attack family on the test set is reported (`fig09`) because rare families
  (Worms, Shellcode, Analysis ...; here the hardest family is Fuzzers) can be missed even when overall accuracy is very high.

## 6. Interfaces

**Command line** - `python predict.py` asks for protocol, service, state, duration, packet counts, bytes, TTLs ...
and prints e.g.

```
Predicted class : MALICIOUS TRAFFIC
Attack probability: 86.29%
```

**Web form** - `python app.py`, then open <http://127.0.0.1:5000>. Buttons *Load normal example* /
*Load attack example* fill the form with real test records. API:
`curl -X POST http://127.0.0.1:5000/api/predict -H "Content-Type: application/json" -d "{\"proto\":\"tcp\",\"sbytes\":500}"`

Only the 17 most important features are asked; the remaining model features are set to the training median
(numeric) / most frequent value (categorical). `--csv` mode accepts all columns of the dataset.

## 7. Limitations (mention in your report / viva)

* UNSW-NB15 is a *simulated* lab dataset; real-world traffic differs, so real deployment needs fresh data.
* The saved model is a binary classifier (normal / attack). Multi-class attack-family classification
  (the dataset's `attack_cat` column) is a natural extension.
* Class imbalance of attack families: rare families have fewer examples (class weights / SMOTE could be tried).
* The prediction on hand-typed values is only as good as the values supplied; it is an educational demo,
  not a production IDS.

## 8. Quick viva answers

* **Why Random Forest usually wins?** An ensemble of many decorrelated trees: captures non-linear feature
  interactions, lower variance than one tree, robust to unscaled/skewed features.
* **Why stratified split / CV?** Keeps the normal : attack proportion identical in every fold / split.
* **Why not accuracy only?** With imbalance, accuracy can look high while attacks are missed; recall and the
  confusion matrix show the real detection ability.
* **What does GridSearchCV do?** Tries every combination of the listed hyper-parameters with 5-fold CV and
  keeps the best by the chosen score (F1 of the attack class).
* **What is data leakage here?** Using columns that reveal the answer (e.g. `attack_cat`) or identify a
  single connection (IPs, ports, timestamps) - the model would look perfect but fail on new traffic.
